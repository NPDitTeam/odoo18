# ระบบปล่อยเช่า Odoo — คู่มือตั้งค่าและใช้งาน

## ภาพรวม

ลูกค้าหนึ่งราย = **หนึ่งฐานข้อมูล** = **หนึ่งโดเมนย่อย** ข้อมูลแยกขาดจากกันจริง
ไม่ใช่แค่กรองด้วยสิทธิ์ — ต่อให้โค้ดมีช่องโหว่ ลูกค้าก็ยังเห็นข้อมูลข้ามกันไม่ได้

```
                    แอป HR (ตัวเดียว ทุกลูกค้า)
                              │ กรอกรหัสองค์กร
                              ▼
        npd-solution.com ── NPD_Logistics ── ศูนย์ควบคุม
                              │                • ทะเบียนลูกค้า + สัญญา
                              │                • ปุ่มสร้าง/ต่ออายุ/ระงับ/ยกเลิก
                              │                • cron ตรวจหมดอายุรายวัน
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
      abc.npd-solution  xyz.npd-solution  ...
      DB: abc           DB: xyz
      (npd_saas_client บังคับใช้สัญญาในตัวเอง)
```

## โมดูลสองตัว

| โมดูล | ติดตั้งที่ไหน | หน้าที่ |
|---|---|---|
| `npd_saas_manager` | ศูนย์ควบคุมเท่านั้น | ทะเบียนลูกค้า สร้าง/ต่ออายุ/ระงับ/ยกเลิก |
| `npd_saas_client` | DB ต้นแบบ (จึงติดไปกับลูกค้าทุกราย) | อ่านสัญญาแล้วบังคับใช้ ล็อกเมื่อหมดอายุ |

สัญญาถูก **เขียนลง** DB ลูกค้า ไม่ใช่ให้ DB ลูกค้าวิ่งมาถามศูนย์ควบคุม
ระบบลูกค้าจึงบังคับใช้สัญญาได้แม้ตัดขาดจากศูนย์ควบคุม และศูนย์ควบคุมล่มก็ไม่ทำให้ลูกค้าใช้งานไม่ได้

## ตั้งค่าครั้งเดียวก่อนเริ่ม

### 1. odoo.conf

```ini
dbfilter = ^%d$
```

`%d` คือส่วนโดเมนย่อย — `abc.npd-solution.com` จะเข้า DB ชื่อ `abc`
**ชื่อ DB ต้องตรงกับโดเมนย่อยเสมอ** ไม่งั้นเข้าไม่ถึง

> ศูนย์ควบคุมชื่อ `NPD_Logistics` ไม่ตรงกับ `npd` — ต้องเลือกทางใดทางหนึ่ง
> เปลี่ยนชื่อ DB เป็น `npd` หรือชี้ `npd.npd-solution.com` ผ่าน reverse proxy
> ที่บังคับ DB ให้ ก่อนเปิดใช้จริง

### 2. พารามิเตอร์ระบบ (ตั้งค่า → เทคนิค → พารามิเตอร์ระบบ)

| คีย์ | ค่า |
|---|---|
| `npd_saas.template_db` | `NPD_TEMPLATE` |
| `npd_saas.root_domain` | `npd-solution.com` |

### 3. ปิดหน้าจัดการฐานข้อมูล

```ini
list_db = False
```

**ควรตั้งค่านี้บนเครื่องจริง** — ระบบ Odoo 14 เดิมเคยถูกเจาะผ่านหน้าจัดการฐานข้อมูล
ที่เปิดสาธารณะมาแล้ว การเปิดทิ้งไว้บนเครื่องที่มีหลายฐานข้อมูลยิ่งเสี่ยงกว่าเดิม
เพราะผู้บุกรุกเห็นรายชื่อลูกค้าทุกรายและลบได้ทีเดียวทั้งหมด

โมดูลนี้สร้าง/ลบฐานข้อมูลด้วยตัวเอง ไม่ได้เรียกฟังก์ชันที่ถูกปิดไปพร้อมค่านี้
จึงตั้ง `list_db = False` ได้โดยปุ่มต่าง ๆ ยังทำงานปกติ

### 4. DNS และ SSL

- DNS: เรคคอร์ด `*.npd-solution.com` ชี้มาที่เซิร์ฟเวอร์
- SSL: ใบรับรองแบบ wildcard `*.npd-solution.com`

ทั้งสองอย่างต้องเป็นแบบ wildcard ไม่งั้นรับลูกค้าใหม่ทีต้องออกใบรับรองใหม่ทุกครั้ง

### 5. DB ต้นแบบ

สร้างครั้งเดียว ใช้เป็นแม่แบบของลูกค้าทุกราย

```bash
odoo-bin -c odoo.conf -d NPD_TEMPLATE \
  -i base,npd_hrms_base,npd_hrms_attendance,npd_hrms_api,npd_hrms_payroll,npd_saas_client \
  --without-demo=all --stop-after-init
```

**ห้ามโคลนจาก `NPD_Logistics`** — ข้อมูลพนักงาน เงินเดือน สลิป และลูกค้าของ NPD
จะไปอยู่กับผู้เช่าทั้งหมด และยังติดไปกับ backup ของเขาแม้จะลบทีหลัง

จะใส่ข้อมูลตั้งต้นที่ใช้ร่วมกันได้ เช่น ประเภทการลา นโยบายเงินเดือนมาตรฐาน
แต่ต้องไม่มีพนักงานหรือรายการเงินจริง

## ขั้นตอนรับลูกค้าใหม่

1. เมนู **ปล่อยเช่าระบบ → ลูกค้าผู้เช่าระบบ** → สร้าง
2. กรอก ชื่อองค์กร / รหัสองค์กร / โดเมนย่อย / บริษัท / วันหมดอายุ / โควตาพนักงาน
3. กด **สร้างระบบให้ลูกค้า** — ระบบโคลน DB ต้นแบบ ตั้งค่า และเขียนสัญญาลงไปให้
4. ส่ง **รหัสองค์กร** ให้ลูกค้าไปกรอกในแอปครั้งแรกครั้งเดียว

## วงจรสัญญา

```
active ──(เลยวันหมดอายุ)──► grace ──(พ้นวันผ่อนผัน)──► expired
   ▲                          │                          │
   └──────── ต่ออายุ ─────────┴──────────────────────────┘
```

| สถานะ | เว็บ | แอป | ข้อมูล |
|---|---|---|---|
| `active` | ใช้ได้ | ใช้ได้ | ครบ |
| `grace` | ใช้ได้ + เตือน | ใช้ได้ + แบนเนอร์ | ครบ |
| `suspended` | ล็อก | ล็อก | ครบ |
| `expired` | ล็อก | ล็อก | ครบ |
| `terminated` | ล็อก | ล็อก | ครบ (จนกว่าจะกดลบ) |

cron ตรวจทุกวันตอนตี 1 เลื่อนสถานะและเขียนลง DB ลูกค้าให้อัตโนมัติ

**ล็อกแล้วปลดได้จากศูนย์ควบคุมเท่านั้น** — ผู้ดูแลฝั่งลูกค้าปลดเองไม่ได้ตามเจตนา
มิฉะนั้นการบังคับใช้สัญญาจะไม่มีผลจริง

## การลบข้อมูลลูกค้า

ตั้งใจให้มีสองจังหวะเพื่อกันการลบพลาด

1. **ยกเลิกสัญญา** → ล็อกระบบ แต่ฐานข้อมูลยังอยู่ครบ
2. **ลบฐานข้อมูลถาวร** → กดได้เฉพาะที่ยกเลิกสัญญาแล้ว กู้คืนไม่ได้

ก่อนลบควรส่งข้อมูลคืนลูกค้าและเก็บ backup ไว้ตามข้อตกลง

## ข้อจำกัดที่ยังไม่ได้ทำ

- **สำรองข้อมูลอัตโนมัติ** — ยังต้องทำจากภายนอก (`pg_dump` ตามรอบ)
- **บิล/ใบแจ้งหนี้** — ประวัติการต่ออายุบันทึกยอดเงินไว้ แต่ยังไม่ออกใบแจ้งหนี้ให้
- **โควตาพนักงาน** — ระบบรายงานว่าเกิน แต่ยังไม่บล็อกการเพิ่มพนักงาน
- **แยกเซิร์ฟเวอร์** — รองรับผ่านช่อง "ที่อยู่เซิร์ฟเวอร์" แต่ปุ่มสร้าง/ลบ
  ทำงานได้เฉพาะ DB ที่อยู่บนเครื่องเดียวกับศูนย์ควบคุม
